# 无人机智能巡检与目标检测系统运行指南

> 适用版本：第一轮升级完成后（JWT 认证 + 个人中心 + 管理员后台 + 邮件报告 + 历史多条件查询）。
>
> 本文所有命令默认在**项目根目录**执行。当前工作区为 `E:\gpt_code\UAV-Inspection-System`，正式工程为 `E:\UAV-Inspection-System`，请根据实际位置替换路径。

---

## 1. 运行前准备

### 1.1 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10/11 64 位 |
| Python | 3.10（推荐使用项目对应的 conda 虚拟环境） |
| 浏览器 | Chrome / Edge 等现代浏览器 |
| 显卡 | 有 NVIDIA GPU 时可自动使用 CUDA；无 GPU 时使用 CPU 推理，速度较慢 |
| 磁盘 | 预留至少 2 GB，用于依赖、模型、上传文件和检测结果 |

本文示例使用 conda 环境：

```text
环境名：UAV-Inspection-System
环境路径：E:\conda\envs\UAV-Inspection-System
Python 版本：3.10.21
```

如果你的环境名或路径不同，替换命令中的对应部分即可。

### 1.2 确认项目根目录

项目中必须能看到以下内容：

```text
backend/
frontend/
models/
uploads/
config.yaml
requirements.txt
uav_inspection.db
```

`config.yaml` 中的数据库路径是相对路径：

```yaml
database:
  url: "sqlite:///./uav_inspection.db"
```

因此**必须从项目根目录启动后端**，不要进入 `backend/` 目录再启动，否则可能连接到旧的 `backend/uav_inspection.db`。

## 2. 最小启动流程

如果环境已经装好依赖、模型和数据库，只需要四步：

```powershell
# 1. 进入项目根目录
cd E:\gpt_code\UAV-Inspection-System

# 2. 激活 conda 环境
conda activate UAV-Inspection-System

# 3. 启动后端
uvicorn backend.app:app --host 127.0.0.1 --port 8000

# 4. 另开一个终端，启动前端
python -m http.server 5500 --directory frontend
```

浏览器打开：

```text
http://127.0.0.1:5500/index.html
```

首次运行前还需要完成数据库迁移和管理员创建，见第 3、4 节。

## 3. 首次运行详细步骤

### 3.1 激活 conda 环境

打开 Anaconda Prompt 或 PowerShell：

```powershell
conda activate UAV-Inspection-System
```

如果 PowerShell 提示 `conda` 不是命令，改用 Anaconda Prompt，或直接使用环境内的 Python：

```powershell
& "E:\conda\envs\UAV-Inspection-System\python.exe" --version
```

确认 Python 版本为 3.10：

```text
Python 3.10.21
```

### 3.2 进入项目根目录

```powershell
cd E:\gpt_code\UAV-Inspection-System
```

正式工程则使用：

```powershell
cd E:\UAV-Inspection-System
```

### 3.3 安装依赖

```powershell
pip install -r requirements.txt
```

第一轮升级**没有新增依赖**，JWT 和密码哈希使用的 `python-jose`、`passlib` 已经在 `requirements.txt` 中。

依赖较多（PyTorch、Ultralytics 等），首次安装可能需要较长时间。

### 3.4 检查模型文件

默认模型路径：

```text
models/pretrained/visdrone_yolov8m.pt
```

正常大小约 49.64 MB。

检查是否存在：

```powershell
Get-Item models\pretrained\visdrone_yolov8m.pt
```

如果不存在，执行下载脚本：

```powershell
python download_visdrone_model.py
```

该脚本从 Hugging Face 下载 VisDrone YOLOv8m 权重，需要网络可以访问 Hugging Face。

### 3.5 备份数据库

首次升级前建议备份：

```powershell
Copy-Item uav_inspection.db uav_inspection.db.bak -Force
```

### 3.6 执行数据库迁移

```powershell
python -m backend.database.migrate_round1
```

正常输出类似：

```text
开始执行第一轮数据库迁移...
检查 user 表：
  [add ] user.email
  [add ] user.avatar_path
  [add ] user.updated_at
检查 detection_record 表：
  [add ] detection_record.remark
第一轮数据库迁移完成。
```

说明：

- 脚本只新增字段和表，不删除、不重建已有数据。
- 可以重复执行，已存在的字段会显示 `[skip]`。
- 迁移后原有账号仍可使用原密码登录。
- `backend/app.py` 启动时也会自动执行一次迁移。

迁移新增内容：

| 表 | 新增内容 |
| --- | --- |
| `user` | `email`、`avatar_path`、`updated_at` |
| `detection_record` | `remark` |
| 新表 | `admin_operation_log` |

### 3.7 创建管理员

系统不再内置默认管理员，必须通过独立脚本创建：

```powershell
python -m backend.database.create_admin --username admin --password 你的密码 --email admin@example.com
```

如果用户名已存在，需要将它提升为管理员：

```powershell
python -m backend.database.create_admin --username admin --password 你的密码 --email admin@example.com --promote-existing
```

不传 `--password` 时会交互式输入密码：

```powershell
python -m backend.database.create_admin --username admin
```

创建完成后，使用该账号登录。

普通用户可以在登录页点击“注册账号”自行注册。

### 3.8 配置邮件（可选）

邮件报告使用 163 SMTP。

先在 163 邮箱网页端开启 SMTP 服务，并获取**授权码**（不是邮箱登录密码）。

在启动后端的同一个终端中设置环境变量：

```powershell
$env:UAV_SMTP_USER="你的163邮箱@163.com"
$env:UAV_SMTP_PASSWORD="你的163授权码"
```

配置文件中已经设置：

```yaml
smtp:
  host: "smtp.163.com"
  port: 465
  use_ssl: true
  from_name: "无人机智能巡检系统"
```

不配置邮件也可以正常使用检测、下载、历史、统计和管理员功能；发送报告时会返回明确提示：

```text
邮件服务尚未配置，请设置环境变量 UAV_SMTP_USER 和 UAV_SMTP_PASSWORD
```

### 3.9 配置 JWT 密钥（建议）

开发配置中有一个默认密钥。正式部署时建议通过环境变量覆盖：

```powershell
$env:UAV_JWT_SECRET="一个足够长的随机字符串"
```

没有设置时使用 `config.yaml` 中的开发默认值。

### 3.10 启动后端

确保当前目录是项目根目录，然后执行：

```powershell
uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

看到以下内容表示启动成功：

```text
Uvicorn running on http://127.0.0.1:8000
Application startup complete.
```

验证后端：

```text
http://127.0.0.1:8000/health
```

返回：

```json
{"status": "healthy"}
```

接口文档：

```text
http://127.0.0.1:8000/docs
```

### 3.11 启动前端

另开一个终端，进入项目根目录：

```powershell
python -m http.server 5500 --directory frontend
```

浏览器打开：

```text
http://127.0.0.1:5500/index.html
```

也可以直接双击 `frontend/index.html`，但推荐使用静态服务器方式，行为更稳定。

前端默认请求后端地址：

```text
http://127.0.0.1:8000
```

该地址定义在 `frontend/js/app.js` 的 `API_BASE` 常量中。如果后端端口改变，需要同步修改。

- [ ] 个人中心可以修改用户名和邮箱。
- [ ] 可以上传 JPG/PNG/WebP 头像，大小不超过 2 MB。
- [ ] 可以删除头像。
- [ ] 修改密码后旧密码失效、新密码可以登录。

### 5.2 图片检测

- [ ] 上传 JPG/JPEG/PNG 图片可以检测。
- [ ] 检测完成后显示标注结果图。
- [ ] 显示目标数、推理耗时、图片尺寸和类别统计。
- [ ] 可以下载结果图片。
- [ ] 历史记录中出现该任务。

### 5.3 视频检测

- [ ] 上传 MP4/AVI/MOV/MKV 视频可以检测。
- [ ] 检测期间显示进度和已用时间。
- [ ] 检测完成后结果视频可以播放，时长正常。
- [ ] 可以下载结果视频。
- [ ] 历史记录中出现帧数、FPS、目标数等字段。

- [ ] 可以按文件名模糊查询。
- [ ] 可以按开始/结束日期查询。
- [ ] 可以按图片/视频筛选。
- [ ] 可以按状态筛选。
- [ ] 可以打开详情并查看结果预览。
- [ ] 普通用户看不到其他用户的记录。

### 5.5 统计分析

- [ ] 今日目标占比饼图正常。
- [ ] 今日类别数量条形图正常。
- [ ] 每日目标总数折线图正常。
- [ ] 各类别每日趋势折线图正常。

### 5.6 管理员后台

- [ ] 可以新增用户。

- [ ] 可以重置用户密码。
- [ ] 删除用户时会提示同时删除其检测记录和文件。

- [ ] 可以修改记录的文件名、备注、状态。
- [ ] 可以物理删除检测记录，原始文件和结果文件同步删除。
- [ ] 不能禁用/删除当前登录管理员，不能移除最后一个有效管理员。

### 5.7 邮件报告

- [ ] 个人中心已填写邮箱。
- [ ] 检测完成后点击“发送报告”可以打开弹窗。

## 6. 常见问题

### 6.1 `ModuleNotFoundError: No module named 'fastapi'`

原因：没有激活正确的 conda 环境。

处理：

```powershell
conda activate UAV-Inspection-System
python -c "import fastapi, sqlalchemy, ultralytics; print('OK')"
```

### 6.2 `配置文件不存在：...config.yaml`

原因：没有从项目根目录启动。

处理：

```powershell
cd 项目根目录
uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

### 6.3 登录后历史记录为空

可能原因：

- 当前账号确实没有检测记录。
- 管理员账号只统计自己的记录；查看全部记录请进入“管理员后台 → 检测记录”。
- 数据库连接到了旧库（检查是否从 `backend/` 目录启动）。

### 6.4 前端提示“无法连接后端服务”

检查：

```text
http://127.0.0.1:8000/health
```

如果打不开，说明后端没有启动或端口不一致。

如果后端端口不是 8000，修改 `frontend/js/app.js`：

```javascript
const API_BASE = "http://127.0.0.1:你的端口";
```

### 6.5 页面修改后没有生效

浏览器缓存导致，按：

```text
Ctrl + Shift + R
```

或在开发者工具 Network 面板勾选 `Disable cache`。

### 6.6 视频上传后检测很久没有反应

视频检测是请求内同步逐帧推理，没有后台任务队列。视频越长、分辨率越高，耗时越长。

### 6.7 视频能下载但网页里时长显示 0

结果视频必须使用浏览器支持的 H.264（`avc1`）编码。当前代码已经优先使用 H.264；如果控制台提示回退到 `mp4v`，说明当前 OpenCV 环境缺少 H.264 编码器。

### 6.8 Ultralytics 报 `PermissionError`（Windows）

如果出现类似：

```text
PermissionError: [WinError 5] 拒绝访问：C:\Users\...\Ultralytics\settings.json
```

设置一个可写目录作为 Ultralytics 配置目录：

```powershell
$env:YOLO_CONFIG_DIR="E:\gpt_code\UAV-Inspection-System\.ultralytics"
uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

### 6.9 邮件发送失败

检查：

1. 是否设置了 `UAV_SMTP_USER` 和 `UAV_SMTP_PASSWORD`。
2. 163 邮箱是否开启了 SMTP 服务。
3. 使用的是否是**授权码**，而不是邮箱登录密码。
4. 本机网络是否可以访问 `smtp.163.com:465`。

### 6.10 出现 `error reading bcrypt version`

这是 `passlib` 与新版 `bcrypt` 的版本提示，不影响密码哈希和登录。如果密码功能正常，可以忽略。

### 6.11 管理员账号不存在

执行：

```powershell
python -m backend.database.create_admin --username admin --password 你的密码 --email admin@example.com
```

如果已有同名普通用户：

```powershell
python -m backend.database.create_admin --username admin --password 你的密码 --promote-existing
```

## 7. 停止服务

在运行后端和前端静态服务的两个终端中分别按：

```text
Ctrl + C
```

确认端口释放：

```powershell
Get-NetTCPConnection -LocalPort 8000 -ErrorAction SilentlyContinue
Get-NetTCPConnection -LocalPort 5500 -ErrorAction SilentlyContinue
```

## 8. 数据备份与恢复

### 8.1 备份

停止后端后执行：

```powershell
Copy-Item uav_inspection.db "uav_inspection_$(Get-Date -Format yyyyMMdd_HHmmss).db"
```

上传文件目录也需要备份：

```powershell
Compress-Archive -Path uploads -DestinationPath "uploads_$(Get-Date -Format yyyyMMdd_HHmmss).zip"
```

### 8.2 恢复

停止后端后，把备份的数据库文件复制回 `uav_inspection.db`，并恢复 `uploads/` 目录。

## 9. 部署到服务器时的调整

### 9.1 监听地址

本地测试：

```bash
uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

服务器部署可改为：

```bash
uvicorn backend.app:app --host 0.0.0.0 --port 8000
```

同时需要注意防火墙和安全组端口。

### 9.2 前端 API 地址

服务器上如果前后端同域，建议把 `frontend/js/app.js` 改为相对路径：

```javascript
const API_BASE = "";
```

如果前端和后端分端口部署，改为实际服务器地址：

```javascript
const API_BASE = "http://服务器IP:8000";
```

### 9.3 安全建议

- 必须通过环境变量设置 `UAV_JWT_SECRET`，不要使用开发默认值。
- 不要把 `UAV_SMTP_PASSWORD` 写进代码或提交到 Git。
- 生产环境建议使用 HTTPS 和 Nginx 反向代理。
- SQLite 适合单机、低并发场景；高并发部署建议迁移到 PostgreSQL/MySQL。
- 定期备份 `uav_inspection.db` 和 `uploads/`。
