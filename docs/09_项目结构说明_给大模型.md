## 1. 项目一句话定位

这是一个「无人机智能巡检与目标检测系统」。系统采用前后端分离的 B/S 架构：后端用 **Python + FastAPI** 提供 HTTP 接口，用 **SQLAlchemy + SQLite** 做数据持久化，用 **Ultralytics YOLOv8**（VisDrone 预训练权重）对无人机航拍的**图片和视频**做目标检测；前端用原生 **HTML/CSS/JavaScript + ECharts** 实现登录、检测工作台、历史记录和统计分析页面。

系统的核心能力是：上传航拍图片或视频 → 执行目标检测 → 生成带标注框的结果文件 → 保存检测记录和类别统计 → 在前端回显结果、查看历史、生成统计图表。

## 2. 技术栈与运行方式

| 层面 | 选型 |
| --- | --- |
| 后端框架 | FastAPI，配合 CORS 中间件和 Pydantic 请求模型 |
| 服务器 | Uvicorn |
| ORM | SQLAlchemy（declarative_base + Session） |
| 数据库 | SQLite，配置为 `sqlite:///./uav_inspection.db` |
| 检测模型 | Ultralytics YOLOv8m，权重 `models/pretrained/visdrone_yolov8m.pt` |
| 图像/视频处理 | OpenCV、NumPy、Pillow |
| 密码安全 | passlib + bcrypt（只存哈希，不存明文） |
| 配置 | 根目录 `config.yaml`，由 `backend/config/settings.py` 读取 |
| 前端 | 原生 HTML5 / CSS3 / JavaScript，无构建步骤 |
| 图表 | ECharts 5.5.1，本地文件 `frontend/vendor/echarts.min.js` |
| 图标 | Lucide 0.454.0，本地文件 `frontend/vendor/lucide.min.js` |

典型启动方式：

```bash
# 项目根目录
pip install -r requirements.txt
uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

前端是纯静态文件，可以直接打开 `frontend/index.html`，也可以用任意静态服务器托管。前端默认把后端地址写死为 `http://127.0.0.1:8000`，位置在 `frontend/js/app.js` 的 `API_BASE` 常量。

## 4. 系统分层与调用链

后端是清晰的单向分层，依赖方向自上而下：

```text
浏览器（前端页面）
      │ HTTP / JSON / multipart
      ▼
backend/api/*.py          路由层：定义 URL、解析参数、组装响应、抛 HTTPException
      │ 调用
      ▼
backend/services/*.py     业务层：业务规则、数据库读写、YOLO 推理、文件处理
      │ 使用
      ├── backend/models/*.py      ORM 表模型
      ├── backend/database/*.py    引擎、Session、get_db
      ├── backend/utils/*.py       无状态工具函数
      └── backend/config/settings.py 配置常量
```

三条必须记住的规则：

1. **路由层只做编排**：`api/` 负责接收请求、调用 Service、把结果包装成 `{"success": ..., "message": ..., "data": ...}`，并把异常转成 `HTTPException`。业务逻辑不写在路由里。
2. **数据库会话通过依赖注入**：所有需要数据库的接口都使用 `db: Session = Depends(get_db)`，请求结束后自动关闭会话。
3. **配置只从 `settings.py` 取**：业务代码不直接读 YAML，统一使用 `MODEL_PATH`、`ORIGINAL_DIR`、`RESULT_DIR` 等常量。

推荐阅读顺序（给其他模型）：

```text
backend/app.py
  → backend/api/*.py
  → backend/services/*.py
  → backend/models/*.py
  → backend/utils/*.py
  → frontend/index.html / login.html
  → frontend/js/app.js
  → 各页面 HTML + 对应 JS
```

## 5. 配置与存储

### 5.1 `config.yaml`

根目录的 `config.yaml` 是唯一配置源，主要内容：

- `system`：系统名称、版本、调试开关。
- `server`：默认 `127.0.0.1:8000`（注意：`app.py` 本身不读取这两个字段，实际监听地址由启动 Uvicorn 时的参数决定）。
- `database.url`：`sqlite:///./uav_inspection.db`，相对于启动进程的工作目录解析，通常就是项目根目录。
- `model.path`：`models/pretrained/visdrone_yolov8m.pt`。
- `model.confidence`：0.25；`model.iou`：0.45；`model.image_size`：640。
- `upload.max_size_mb`：500；`image_extensions`：`.jpg/.jpeg/.png`；`video_extensions`：`.mp4/.avi/.mov/.mkv`。
- `storage.original_dir`：`uploads/original`；`storage.result_dir`：`uploads/results`。
- `logging.level`：INFO；`logging.file`：`logs/system.log`。

### 5.2 `backend/config/settings.py`

该模块的职责是：

1. 用 `Path(__file__).resolve().parents[2]` 定位到项目根目录。
2. 读取根目录 `config.yaml`，文件不存在时抛出 `FileNotFoundError`。
3. 把配置摊平成模块级常量，供全项目导入。
4. 在导入时自动创建 `uploads/original`、`uploads/results` 和日志文件所在目录。

### 5.3 文件存储约定

- 上传原始文件统一放在 `uploads/original/`，文件名由 `uuid4().hex + 原扩展名` 生成，避免重名。
- 检测结果统一放在 `uploads/results/`：
  - 图片结果：`{原始文件名去扩展名}_result.jpg`
  - 视频结果：`{原始文件名去扩展名}_result.mp4`
- 结果文件不通过静态目录对外暴露，而是通过 `/api/detection/download/{record_id}` 接口按权限返回。

## 6. 数据模型

当前生效的数据库是项目根目录的 `uav_inspection.db`，包含三张业务表，关系为「一个用户 → 多条检测记录 → 每条记录多条类别统计」。

### 6.1 `user`（用户表）

对应 `backend/models/user.py`。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | Integer 主键 | 用户 ID |
| `username` | String(50)，唯一、索引 | 用户名 |
| `password_hash` | String(255) | bcrypt 密码哈希 |
| `role` | String(20) | 角色，默认 `user`，管理员为 `admin` |
| `status` | Integer | 1 正常，0 禁用，默认 1 |
| `created_at` | DateTime | 创建时间，默认 UTC 当前时间 |

### 6.2 `detection_record`（检测记录表）

对应 `backend/models/detection_record.py`。一条记录代表一次图片或视频检测任务。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | Integer 主键 | 检测记录 ID |
| `user_id` | Integer 外键 → `user.id` | 所属用户 |
| `task_type` | String(20) | `image` 或 `video` |
| `original_name` | String(255) | 用户上传时的原始文件名 |
| `original_path` | String(500) | 原始文件路径 |
| `result_path` | String(500)，可空 | 结果文件路径 |
| `model_name` | String(100) | 使用的模型文件名 |
| `status` | String(20) | `processing` / `completed` / `failed`，当前成功流程只写 `completed` |
| `object_count` | Integer | 检测目标总数 |
| `max_objects` | Integer，可空 | 单帧最大目标数；图片任务等于总数 |
| `average_objects` | Float，可空 | 平均每帧目标数；图片任务等于总数 |
| `inference_time` | Float，可空 | 推理耗时（秒） |
| `frame_count` | Integer，可空 | 视频帧数；图片为 NULL |
| `width` / `height` | Integer，可空 | 媒体宽高 |
| `fps` | Float，可空 | 视频帧率；图片为 NULL |
| `error_message` | String(1000)，可空 | 失败原因 |
| `created_at` | DateTime | 创建时间 |

### 6.3 `detection_class_statistics`（类别统计表）

对应 `backend/models/detection_class_statistics.py`。每条检测记录按类别拆成多行。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | Integer 主键 | 统计记录 ID |
| `record_id` | Integer 外键 → `detection_record.id` | 所属检测任务 |
| `class_id` | Integer | 模型类别 ID |
| `class_name` | String(100) | 类别名称 |
| `count` | Integer | 该类别在本次任务中的检测数量 |

### 6.4 两个数据库文件的区别

- **根目录 `uav_inspection.db`**：当前生效的数据库，包含 `user`、`detection_record`、`detection_class_statistics` 三张表。测试时约有 1 个用户、10 条检测记录、75 条类别统计。
- **`backend/uav_inspection.db`**：旧版遗留库，表结构为 `users`（含明文 `password` 字段）和 `detection_records`，且没有数据。当前代码不会读取它，可以视为历史残留。

## 7. 后端逐文件说明

### 7.1 `backend/app.py`（应用入口）

导入时依次完成：

1. 调用 `Base.metadata.create_all(bind=engine)` 自动创建已注册的表。
2. 创建 FastAPI 实例，标题为「无人机智能巡检与目标检测系统」，版本 1.0.0。
3. 添加 CORS 中间件：允许所有来源、方法、请求头（`allow_origins=["*"]`），方便前端从其他端口或 `file://` 调用。
4. 注册四个路由模块：
   - `auth_router` → `/api/auth`
   - `detection_router` → `/api/detection`
   - `statistics_router` → `/api/statistics`
   - `history_router` → `/api/history`
5. 提供两个无前缀接口：
   - `GET /`：返回系统名称、版本、运行状态。
   - `GET /health`：健康检查，返回 `{"status": "healthy"}`。

注意：`api/statistics_old1.py` **没有被注册**，是旧版遗留文件，不影响运行。

### 7.2 `backend/database/`

- `database.py`：
  - 使用 `create_engine(DATABASE_URL, connect_args={"check_same_thread": False})` 创建 SQLite 引擎。
  - 创建 `SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)`。
  - 定义 `Base = declarative_base()`。
  - `get_db()` 是 FastAPI 依赖：请求开始时创建 Session，`finally` 中关闭。
- `init_db.py`：导入所有模型后手动执行 `Base.metadata.create_all`，用于初始化表。
- `create_user.py`：创建默认管理员 `admin / 123456`。注意该脚本直接构造 `User(password="123456")`，与当前 `User.password_hash` 字段不一致，属于历史遗留写法，实际默认用户应以数据库中已有记录为准。

### 7.3 `backend/models/`

三个 ORM 模型分别对应第 6 节的三张表。`models/__init__.py` 和 `database/__init__.py` 都会导入这三个模型，确保 `create_all` 时能注册到全部表。

### 7.4 `backend/api/`

#### `auth.py`（前缀 `/api/auth`）

- `POST /register`：请求体 `{username, password}`，调用 `AuthService.register_user`。
- `POST /login`：请求体 `{username, password}`，调用 `AuthService.login_user`。
- `POST /change-password`：请求体 `{user_id, old_password, new_password, two_new_password}`，调用 `AuthService.change_password`。

三个接口都遵循：`ValueError` → 400/401，其他异常 → 500。登录成功不发放 Token，只返回 `user_id`、`username`、`role`。

#### `detection.py`（前缀 `/api/detection`）

- `POST /image?user_id=`：
  1. `ImageService.save_upload_iamgefile` 保存并校验图片。
  2. `check_image` 验证图片可读，失败则删除临时文件。
  3. 调用 `detection_service.detect_image`。
  4. 返回 record_id、原始/结果路径、目标数、推理耗时、宽高、检测框列表和类别统计。
- `POST /video?user_id=`：
  1. `VideoUploadService.save_upload_video` 保存并校验视频。
  2. 调用 `detection_service.detect_video`。
  3. 返回 record_id、结果视频路径、帧数、总目标数、单帧最大目标数、平均每帧目标数、推理耗时、FPS、宽高和类别统计。
- `GET /download/{record_id}?user_id=`：
  1. 调用 `DownloadService.get_result_file`，同时校验记录归属和文件存在。
  2. 用 `FileResponse` 返回结果文件，`media_type` 为 `application/octet-stream`。

#### `history.py`（前缀 `/api/history`）

- `GET ""?user_id=&page=&page_size=&task_type=`：调用 `HistoryService.get_history_list`，返回分页列表。
- `GET /{record_id}?user_id=`：调用 `HistoryService.get_history_detail`，返回单条记录详情和类别统计。

#### `statistics.py`（前缀 `/api/statistics`）

- `GET /overview?user_id=`：总体统计。
- `GET /classes?user_id=`：全部已完成任务的类别汇总。
- `GET /record/{record_id}?user_id=`：单次检测任务的统计详情。
- `GET /trend?user_id=`：按日期的检测次数和目标总数趋势。
- `GET /class-trend?user_id=`：按日期、按类别的趋势，返回 `{dates, series}`。

#### `statistics_old1.py`（未注册）

旧版文件，路由前缀写成 `/api/history`，包含列表、详情和删除接口，但没有被 `app.py` 导入。当前系统的「删除记录」功能实际上不存在，README 中的相关描述属于旧版遗留。

### 7.5 `backend/services/`

#### `auth_service.py`

- 使用 `CryptContext(schemes=["bcrypt"])`。
- `hash_password` / `verify_password`：bcrypt 哈希与校验；密码超过 72 字节直接拒绝。
- `register_user`：检查用户名唯一、长度 3–50，密码不少于 6 位且不超过 72 字节；默认 `role="user"`、`status=1`。
- `login_user`：按用户名查询；不存在、密码错误统一提示「用户名或密码错误」；`status != 1` 提示「用户账号已被禁用」。
- `change_password`：校验旧密码、新密码长度、新旧不能相同、两次输入一致，最后更新哈希。

#### `detection_service.py`（核心）

- 模块底部创建全局单例 `detection_service = DetectionService()`。
- `DetectionService.model` 惰性加载：第一次推理才调用 `load_model()`，之后复用。
- `detect_image`：
  1. `ensure_model()`。
  2. `model.predict`，参数来自配置（conf=0.25、iou=0.45、imgsz=640）。
  3. `parse_detections` 解析每个框的类别、置信度和 xyxy 坐标。
  4. `calculate_class_statistics` 汇总类别。
  5. `save_annotated_image` 用 `result.plot()` 画框并保存为 JPG。
  6. `DetectionRecordService.create_image_record` 写主记录和类别统计。
- `detect_video`：
  1. `ensure_model()`。
  2. 用 `cv2.VideoCapture` 打开视频，读取 FPS、宽高、总帧数；FPS 读取失败时回退 25。
  3. 创建结果视频写入器。
  4. 逐帧 `model.predict`，解析检测框，累计总目标数、单帧最大目标数、类别统计，用 `result.plot()` 标注后写入结果视频。
  5. 计算平均每帧目标数和推理耗时。
  6. `DetectionRecordService.create_video_record` 写主记录和类别统计。
- `resolve_video_fourcc(width, height, fps)`：
  - 浏览器 HTML5 `<video>` 不支持 MPEG-4 Part 2（`mp4v`），因此按 `avc1 → H264 → mp4v` 的顺序选择编码。
  - 每个候选先写一个单帧探测文件，检查能打开、文件非空；声明为 H.264 时还必须包含 `avcC` 描述块，通过后才用于正式输出。
  - 全部失败时回退 `mp4v` 并打印警告。该机制保证结果视频优先为浏览器可播放的 H.264。

#### `detection_record_service.py`

- `create_image_record`：写 `DetectionRecord(task_type="image", status="completed")`，`max_objects` 和 `average_objects` 都等于 `object_count`；`db.flush()` 取得 id 后逐条写类别统计，最后 `commit`。
- `create_video_record`：写视频记录，保存帧数、FPS、最大/平均目标数等；同样先 flush 再写类别统计。
- 两个方法异常时都会 `db.rollback()` 并重新抛出。

#### `image_upload_service.py`

- `save_upload_iamgefile`（注意方法名拼写为 `iamge`）：
  1. 检查文件名非空。
  2. 用 `is_allowed_extension` 校验图片扩展名。
  3. 生成 UUID 文件名。
  4. `await upload_file.read()` 读取全部内容，校验不超过 500 MB。
  5. 写入 `uploads/original/` 并返回路径。
- `delete_file`：删除指定文件，用于图片校验失败时清理。

#### `video_upload_service.py`

- `save_upload_video`：与图片上传类似，校验视频扩展名和大小后写入 `uploads/original/`。

#### `download_service.py`

- `get_result_file`：按 `record_id + user_id` 查询记录；记录不存在、无 `result_path`、文件不存在或不是文件时抛出 `ValueError`。
- 根据 `task_type` 生成下载文件名：图片为 `{原文件名}_result.jpg`，视频为 `{原文件名}_result.mp4`。

#### `history_service.py`

- `get_history_list`：校验 `page >= 1`、`1 <= page_size <= 100`；按用户过滤，可选 `task_type`；按 `created_at` 倒序；返回 `items/page/page_size/total/pages`。
- `get_history_detail`：按 `record_id + user_id` 查询主记录，再查该记录的类别统计，返回完整字段和 `class_statistics` 列表。

#### `statistics_service.py`

- `get_user_overview`：只统计 `status == "completed"` 的记录，汇总任务总数、图片数、视频数、目标总数、平均推理时间。
- `get_user_class_statistics`：把 `detection_class_statistics` 与 `detection_record` 连接，按类别分组求和，按数量降序。
- `get_record_statistics`：返回单次任务的字段和按数量降序的类别统计。
- `get_detection_trend`：用 `func.date(created_at)` 分组，返回按日期升序的 `{date, task_count, object_count}`。
- `get_class_trend`：按日期和类别分组求和，返回 `{dates, series}`；某个类别在某天没有数据时用 0 补齐。

### 7.6 `backend/utils/`

- `detection_utils.py`：
  - `parse_detections(result, model_names)`：把 YOLO 结果转成 `{class_id, class_name, confidence, bbox}` 列表。
  - `calculate_class_statistics(detections)`：按类别汇总数量。
  - `update_class_statistics(class_statistics, detections)`：视频逐帧累计类别数量。
  - `save_annotated_image`：用 `result.plot()` 画框并保存 JPG。
  - `get_image_size`：用 OpenCV 读取宽高。
- `file_utils.py`：`generate_unique_filename`（UUID + 小写扩展名）、`get_file_extension`、`is_allowed_extension`、`is_image_file`、`is_video_file`。
- `image_utils.py`：`check_image`（OpenCV 能否读取）、`get_image_size`。
- `result_utils.py`：检测结果的 JSON 序列化 / 反序列化（当前主流程未使用）。

## 8. 前端结构与功能

前端是无构建步骤的原生静态页面，5 个 HTML 页面共享同一套 `css/style.css` 和 `js/app.js`。

### 8.1 页面

- `index.html`：入口页。读取 `localStorage` 中的 `uav.session`，已登录跳 `statistics.html`，未登录跳 `login.html`。
- `login.html`：左右两栏布局。左侧为背景图 + 品牌信息，右侧为登录 / 注册切换表单。
- `statistics.html`：默认首页。顶部 4 个统计卡片，下面是饼图、条形图、每日目标总数折线图和各类别每日趋势折线图。
- `detection.html`：图片 / 视频检测工作台。通过 `?mode=image` 或 `?mode=video` 切换模式，包含拖拽上传、预览、进度、指标、类别分布、目标明细和下载。
- `history.html`：历史记录列表，支持全部 / 图片 / 视频筛选、分页、详情弹窗和结果预览。

### 8.2 `js/app.js`（共享核心）

- `API_BASE = "http://127.0.0.1:8000"`。
- 会话：`getSession/setSession/clearSession`，localStorage 键为 `uav.session`，内容为 `{user_id, username, role}`。
- `requireAuth()`：没有会话时跳转 `login.html`。
- `api(path, options)`：统一 fetch 封装，自动拼接查询参数和 JSON body，非 2xx 时抛出带 `detail` 的错误。
- `downloadUrl(recordId, userId)`：生成下载接口地址。
- `init({active, title, subtitle})`：鉴权后渲染侧边栏和顶栏，绑定用户菜单、移动端抽屉、改密弹窗和时钟。
- `toast(message, type)`：右下角提示。
- `chartBase()` 与 `CHART_COLORS`：ECharts 通用主题和配色。
- 侧边栏菜单顺序：统计分析 → 图片检测 → 视频检测 → 历史记录 → 密码修改 → 退出登录。

### 8.3 各页面脚本

- `login.js`：登录 / 注册切换、密码显隐、表单校验、调用 `/api/auth/login` 和 `/api/auth/register`，登录成功后写入会话并跳转 `statistics.html`。
- `statistics.js`：
  - 同时请求 `/api/statistics/overview`、`/trend`、`/class-trend`。
  - 统计卡片：今日任务、今日目标、累计任务、累计目标。
  - 「今日」数据取 `class-trend` 中当天那一列，派生饼图和条形图。
  - 每日目标走势：目标总数折线 + 检测次数柱状；超过 14 天启用 dataZoom。
  - 各类别趋势：一个类别一条折线，图例可切换。
- `detection.js`：
  - 根据 `?mode=` 决定图片或视频模式。
  - 本地预览用 `URL.createObjectURL`；检测结果通过下载接口取回 Blob，图片强制为 `image/jpeg`，视频强制为 `video/mp4`，再交给 `<img>` / `<video>`。

  - 结果区渲染指标、类别分布条和目标明细表（图片模式）。
- `history.js`：分页查询历史列表，渲染类型 / 状态徽标；详情弹窗再次请求详情接口并加载结果预览。

- 响应式断点：1200px（统计卡两列）、960px（侧边栏变抽屉、登录左栏隐藏）、720px（单列）。

## 9. 核心业务流程

### 9.1 登录、注册与修改密码

```text
login.html
  → login.js
  → POST /api/auth/login
  → AuthService.login_user
  → 查询 user、校验 status、bcrypt 校验密码
  → 返回 {user_id, username, role}
  → 前端写入 localStorage["uav.session"]
  → 跳转 statistics.html
```

- 登录不发放 Token；后续接口通过显式传 `user_id` 识别用户，这是演示性质的简化鉴权。
- 注册调用 `/api/auth/register`，成功后不自动登录，需切回登录页。
- 改密通过侧边栏或用户菜单打开弹窗，调用 `/api/auth/change-password`，成功后清除会话并要求重新登录。

### 9.2 图片检测

```text
detection.html?mode=image
  → 选择文件（前端校验扩展名和大小）
  → POST /api/detection/image?user_id=
  → ImageService 保存到 uploads/original
  → check_image 校验可读
  → DetectionService.detect_image
  → YOLO 推理 → parse_detections → calculate_class_statistics
  → result.plot() 保存 uploads/results/xxx_result.jpg
  → DetectionRecordService 写 detection_record + detection_class_statistics
  → 返回结果
  → 前端通过 /api/detection/download/{record_id} 取回结果图并显示
```

### 9.3 视频检测

```text
detection.html?mode=video
  → 选择视频
  → POST /api/detection/video?user_id=
  → VideoUploadService 保存到 uploads/original
  → DetectionService.detect_video
  → cv2.VideoCapture 读取 fps/宽高/帧数
  → resolve_video_fourcc 选择 H.264（avc1）编码器
  → 逐帧 YOLO 推理、绘制、写入结果视频
  → 累计目标数、单帧最大、平均每帧、类别统计、推理耗时
  → DetectionRecordService 写记录和类别统计
  → 返回结果
  → 前端通过下载接口取回 MP4，生成 Blob URL 播放
```

视频检测是**同步阻塞**的：在请求内完成全部逐帧推理，没有任务队列或后台任务。长视频会长时间占用请求，前端通过进度提示等待。

### 9.4 结果下载与预览

- 下载接口同时校验 `record_id` 和 `user_id`，越权返回 404。
- 下载响应使用 `application/octet-stream`，因此前端不能直接把接口地址当图片/视频的 `src` 使用，而是先 `fetch` 成 Blob，再按类型重新包装后交给 `<img>` / `<video>`。
- 图片结果固定为 JPG；视频结果固定为 MP4。

### 9.5 历史记录

```text
history.html
  → GET /api/history?user_id=&page=&page_size=&task_type=
  → 返回 items/page/page_size/total/pages
  → 渲染表格和分页
  → 点击详情 → GET /api/history/{record_id}?user_id=
  → 返回主记录字段 + 类别统计 + 结果路径
  → 弹窗内再通过下载接口加载结果预览
```

### 9.6 统计分析

```text
statistics.html
  → GET /api/statistics/overview     → 总体数字
  → GET /api/statistics/trend        → 每日任务数/目标数
  → GET /api/statistics/class-trend  → 每日各类别数量
  → 前端派生「今日」饼图和条形图
  → ECharts 渲染四类图表
```

所有统计只计算 `status == "completed"` 的记录。

## 12. 已知遗留与注意事项

其他模型在修改本项目时应先了解以下事实：

1. **`api/statistics_old1.py` 未被注册**：它是旧版文件，路由前缀甚至是 `/api/history`，不要误以为它参与运行。
2. **README 与代码存在偏差**：
   - README 写了「检测记录删除」，但当前没有注册删除接口；删除逻辑只存在于旧文件中。
   - README 未提及视频检测、注册、改密和统计图表，但这些功能实际存在。
   - README 未说明 `scripts/` 为空。
3. **`backend/uav_inspection.db` 是旧库**：表结构为 `users` + `detection_records`，当前代码不读取它；真正生效的是根目录 `uav_inspection.db`。
4. **数据库路径依赖工作目录**：`sqlite:///./uav_inspection.db` 是相对路径。如果从 `backend/` 目录启动，可能连接到另一份数据库；建议始终从项目根目录启动 Uvicorn。
5. **鉴权是简化模式**：没有 JWT、没有中间件校验，接口通过 `user_id` 查询参数识别用户；只有下载和历史查询做了归属校验，其他接口依赖前端传值。
6. **视频检测同步执行**：没有任务队列，长视频会阻塞请求；`status` 字段虽然支持 `processing/failed`，但当前成功流程只写 `completed`，失败不会落库。
7. **视频编码**：结果视频必须使用浏览器支持的 H.264（`avc1`）。`mp4v` 文件虽然能下载、能在 VLC 播放，但浏览器会报 `DEMUXER_ERROR_NO_SUPPORTED_STREAMS` 且时长为 0。
8. **前端 API 地址写死**：`frontend/js/app.js` 的 `API_BASE` 是 `http://127.0.0.1:8000`。迁移到服务器或改变端口时必须修改，否则前端会请求错误地址。
9. **前端有 5 个页面且必须同层**：页面之间用相对路径跳转，`css/`、`js/`、`assets/`、`vendor/` 也必须保持相对位置。
10. **登录页背景图**：CSS 中引用 `../assets/login-bg.jpeg`，路径相对于 `css/style.css`；旧图 `login-bg1.png` 已不引用。

## 13. 给下游大模型的速记

1. 新增接口：在 `backend/api/` 写路由，调用 `services/`，最后在 `backend/app.py` 注册。
2. 新增业务逻辑：写进 `backend/services/`，保持 `@staticmethod` 或单例风格。
3. 新增数据表：在 `backend/models/` 定义 ORM 类，并在 `models/__init__.py`、`database/__init__.py`、`init_db.py` 中导入，确保 `create_all` 能注册。
4. 取配置一律走 `backend.config.settings`，不要在业务代码里直接读 YAML。
5. 数据库操作统一使用注入的 `db: Session`，异常时 `db.rollback()`。
6. 接口响应保持 `{success, message, data}` 结构。
7. 上传文件先校验扩展名和大小，再落盘；文件名使用 UUID。
8. 结果文件统一放 `uploads/results/`，图片用 JPG，视频用 H.264 编码的 MP4。
9. 前端页面共享 `js/app.js`，新增页面应调用 `App.init({active, title, subtitle})` 复用侧边栏、顶栏和鉴权。
10. 修改前端后注意浏览器缓存；开发时可按 `Ctrl+Shift+R` 强制刷新。
